# 《品保工程師的一天》完整遊戲設計 v1.0

## 作品定位

單人、繁體中文、桌機與手機可玩的敘事策略小遊戲。一輪約 10–15 分鐘，以虛構的「第零製造所」為舞台：伺服器機櫃、液冷迴路與 Manifold 分歧管是主力產品。所有名稱、批號、數據、角色與文件皆為虛構，不描寫任何真實公司或事件。產品流程只作為故事情境，不是實際檢驗規範或放行指引。

玩家是一位 QE。任務是讓示範批次 R-00 在下班前完成品質判定、追溯與交接。主管的願望是零客訴、零停線、零加班費；玩家的願望是便當還溫的。喜劇從企業系統介面與荒謬對話出發，最後落在責任、資訊斷點與界線被侵蝕的真實痛感。

## 完整產品願景

正式版以五個工作日為一章：第一天進料與追溯，第二天製程能力，第三天變更與客訴，第四天跨部門稽核，第五天批次交付與改善驗證。玩家保留職能資格、文件線索與同事互助關係；每天重新計算壓力與停線時間。長期目標是把「靠某個人記得」的工作轉成可交接的制度。後續章節加入供應商改善、外包加工迴圈、客戶稽核與設備異常，但不加入真實組織資訊。

MVP 僅實作完整第一天，所有本文件標示「MVP」的功能均可遊玩；五日章節、人物關係、實際圖面解謎與多批次排程是後續擴充，並非已完成內容。

## 核心循環與數值（MVP）

閱讀事件 → 查看當前職能與影響預覽 → 選擇處置 → 數值變動與文件/支線進度 → 交接紀錄 → 下一個時段。十二個日班時段從 08:30 到 18:00；願意接電話會進入三個夜間時段 19:10、21:40、23:58。事件時鐘是敘事排程；停線分鐘累積於另一計數器，不會改變時段，也不是現實工時模擬。

| 指標 | 初始 | 範圍 | 意義與取捨 |
|---|---:|---|---|
| 品質 | 70 | 0–100 | 批次控制完整程度；草率放行降低，隔離/驗證提高 |
| 壓力 | 24 | 0–100 | 接責任、跳過午餐、加班提高；界線與交接降低 |
| 信用 | 50 | 0–100 | 部門對處置與交接的信任；不等於聽話指數 |
| 停線 | 0 | 非負分鐘 | 保留批次與查證的代價；不是失敗指標 |
| 加班 | 0 | 非負分鐘 | 僅夜間事件增加，結局揭露代價 |

結果採加總後限制範圍；不以壓力達 100 強迫玩家立即死亡，避免單一指標切斷支線。當事件建議職能與玩家職能一致時，該選項另得品質 +2、信用 +2、壓力 -2（預覽含此加成）。若選項要求已解鎖職能，可在選擇前切換。沒有計時按鈕、體力付費或真實工廠檢驗指示。

## 職能與轉職（MVP）

QE 是永久初始職能。事件首次指定新職能，解鎖該職能的代班資格並自動派任。累計處理兩起指定該職能的事件，變成永久資格。代班職能在下一時段回到 QE；永久職能可跨時段保留，新的派任仍可覆蓋。玩家可隨時從已解鎖名單切換；職能不消耗資源。

| 職能 | 劇情定位 | 首次主線派任 |
|---|---|---|
| QE | 協調、文件與跨部門交接 | 初始 |
| IQC | 進料、批號與檢驗紀錄 | 08:30 QD 座混箱 |
| SQE | 供應商、外包與 NCR/CAR | 09:10 外包回覆 |
| PQE | CNC 加工、製程與量測 | 10:40 CMM 偏差 |
| IPQC | 巡檢、焊接與製程異常 | 11:20 焊接換班 |
| FQC | 最終檢驗、氣密/沉水紀錄 | 13:10 測試紀錄 |
| CQE | 客訴、證據與對外回覆 | 15:10 現場回報 |
| OQC | 出貨、包材與標籤 | 17:10 裝箱放行 |

## 主線劇本（MVP）

1. 08:30：QD 座來料批號混箱，決定保留追溯或以外觀放行。
2. 09:10：外包加工回覆「以前都可以」，要求證據、開 NCR/CAR 或接受口頭承諾。
3. 09:50：從隨機池抽一件插單。
4. 10:40：CNC 件 CMM 結果偏移，重建量測與加工關聯或將不合格交給 RD 特採。
5. 11:20：焊接交班未留下參數版本，IPQC 被呼叫。
6. 12:05：午餐時有人說「五分鐘」，第一次練習界線。
7. 13:10：Manifold 氣密/沉水紀錄缺序號，結果與追溯必須分別處理。
8. 14:10：EC 變更與舊圖面並存；有足夠線索時出現隱藏的版本履歷。
9. 15:10：客戶回報液冷迴路問題，需要 CQE 整理證據、界定責任。
10. 16:10：再抽一件隨機事件，兩次抽取不重複。
11. 17:10：機櫃出貨，包材、標籤、保護與未結案事項一起到場。
12. 18:00：交接與門禁。玩家可以下班；也可以接受一句「只問一下」，進入夜班。
13. 19:10：群組訊息，被迫遠端擔任 SQE。
14. 21:40：當客訴與圖面爭議同時出現，是否保存證據或接下所有工作。
15. 23:58：補交接，當明天的自己還沒上班，今天的自己已經幫他加班。

每個事件 2–4 個選項，有數值預覽與敘事後果。選擇後先呈現回覆，再由玩家點下一時段；避免大量事件瞬間跳過。

## 支線（MVP，三條均有三階段）

**A. 供應商說以前都可以**：外包回覆保留 NCR/CAR → CMM 偏差補量測依據 → 出貨保留改善與追蹤要求。每階段完成才可進下一階段。結案獎勵信用 +6、品質 +4。目的是把責任從個人口頭承諾變成文件與追蹤，不以自動結案取代改善驗證。

**B. 消失的批號**：進料鎖定箱號 → 測試補回序號關聯 → EC 核對版本歷程。結案獎勵信用 +6、品質 +4，解鎖隱藏事件「幽靈版本」與結局資格。過了關鍵節點才發現前一階段缺失時，明確標示「本輪錯過」。

**C. 便當保衛戰**：午餐指定窗口 → 客訴建立交接而非個人全天候承接 → 下班關閉通知/交接離場。結案獎勵信用 +6、壓力 -8。第三階段只在前兩階段達成後可完成。低壓力並不代表案件自動消失，而是它有人負責。

## 隨機事件（MVP）

八件事件以種子亂數抽取兩件、無重複：QD 方向標示、CMM 校驗到期、紙箱受潮、RD 特採缺期限、外包焊接色差、機櫃腳輪刮傷、巡檢表複製貼上、檢驗紀錄照片模糊。各有 3 個處置，每件均可觸發代班與影響數值。相同種子與同樣選擇可重現流程，重新開始會產生新種子。

## 隱藏內容與結局（MVP）

隱藏事件一 **幽靈版本**：14:10 前完成追溯支線前兩階段，出現封存舊版 EC 履歷的選項。完成追溯且封存證據，取得隱藏結局「不是你記錯，是版本在漂移」。

隱藏事件二 **門禁真的可以刷出去**：18:00 前完成便當支線前兩階段，出現由交接窗口承接的離場選項；完成第三階段並離場，取得隱藏結局「下班是一個完整的句子」。

結局優先序：便當隱藏結局 → 版本隱藏結局 → 品質 <45「放行很快，回來也很快」→ 壓力 ≥80 或加班 ≥200「明天見，今天還沒結束」→ 品質 ≥80 且信用 ≥65「文件都在，人還在」→「普通的一天，異常的一生」。隱藏結局條件優先於指標；結局同時揭露所有指標，達到隱藏條件不會遮蔽壓力或低品質。共六個可收集結局。

## UI、音調與無障礙（MVP）

企業系統的側欄、版本號、追蹤單、交班紀錄，混合 CSS 像素人物、機櫃與深色終端機。暖橘色表示工作進度，薄荷綠表示可行處置，粉紅表示壓力；不只靠顏色傳遞意義。無音效、無外部字型、無圖片載入。按鈕可鍵盤操作，模態視窗可 Esc 關閉，焦點可見，支援減少動態效果，手機改為單欄。

文案守則：笑點針對流程矛盾與系統，不嘲笑第一線人員。不得使用公司名稱、真實供應商/同事/地址/Logo/料號等可識別資訊。所有故事用角色職稱，例如「製程窗口」「研發窗口」。以「特採、停線、品保、圖面、資料、專案、滑鼠、伺服器」等台灣用語為主。

## 存檔、完成定義與後續架構

MVP：自動保存在瀏覽器 localStorage；重新整理可接續；已看結局獨立保存，開新局不清除。儲存失敗時仍可繼續，但提示無法存檔。支援下載文字交接報告。完整第一天、兩個隱藏事件、六個結局、八職能、三支線與八件隨機池均可操作；不需要伺服器或安裝套件。

後續：將事件拆成章節資料、增加資產與可選音效、改善系統加入跨日追蹤期限、新增關係值與角色對話、讓量測/版本對照成為小型解謎、加入測試紀錄與異常照片的虛構資產、增加存檔匯出/匯入。架構與擴充契約詳見 ARCHITECTURE.md。
